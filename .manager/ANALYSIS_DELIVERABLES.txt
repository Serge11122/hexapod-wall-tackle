KEY FINDINGS:
=============

ROOT CAUSE:
- Timer-dev detected premature eta_done signal (process still running)
- Timer-dev correctly decided to IGNORE the signal
- BUG: Timer-dev did NOT clear/delete the file after ignoring
- Timer-eta then waits forever for timer-dev to clear (deadlock)

SUPERVISOR FAILURE:
- Supervisor checked: "Is the decision correct?" (YES)
- Supervisor did NOT check: "Is the cleanup complete?" (NO)
- Supervisor missed 4 key signals:
  1. File age (eta_done was 9+ min old, not cycling)
  2. /teta interval (no monitoring calls for 10+ min)
  3. State transition (ignored without cleared)
  4. Log correlation (ignored + waiting = incomplete)

THE FIX:
- One line of code: rm -f "$ETA_DONE"
- Location: timer/tmux_timer_dev.sh line ~369
- Effect: Unblocks timer-eta for next monitoring cycle

RECURRENCE RISK:
- Without supervisor enhancements: HIGH
- With Level 1+2 enhancements: LOW
- With all 4 levels + code review: MINIMAL

IMPROVEMENT LEVELS (by complexity):
====================================

Level 1 (EASY): File Age Checking
- Check stat -c %Y on eta_done
- Flag if >10 min old in monitoring mode
- Cost: 3 bash lines

Level 2 (EASY): /teta Interval Tracking
- Grep last "SENT /teta" from timer_eta.log
- Compute elapsed time
- Flag if >7 min (5 min interval + 2 min tolerance)
- Cost: log parsing + timestamp computation

Level 3 (MEDIUM): Log Correlation
- Check timer_dev.log for "ignored without cleared"
- Check timer_eta.log for "waiting"
- Detect both patterns = deadlock
- Cost: pattern matching

Level 4 (HARD): State Machine Validator
- Model expected state transitions
- Verify actual logs match expected sequence
- Detect incomplete transitions
- Cost: state diagram + validation
